# Supervisor-Worker Workflow

## 역할

### Supervisor

- 요구사항 해석
- 작업 범위 설정
- 수정 가능/금지 영역 지정
- 구현 순서 정의
- 위험 변경 판단
- Worker 질문에 대한 결정
- 최종 검토

### Worker

- Supervisor 계획에 따른 구현
- 작은 단위 수정
- 테스트 또는 빌드 검증
- 막히면 질문
- 완료 후 변경 내용 보고

## Supervisor Plan 형식

```txt
작업 목표:
수정 허용 영역:
수정 금지 영역:
구현 순서:
중단 조건:
검증 방법:
```

## Worker Question 형식

```txt
현재 작업:
진행한 내용:
막힌 지점:
가능한 선택지:
내 판단:
필요한 결정:
```

## Worker Report 형식

```txt
작업 요약:
변경 파일:
변경 내용:
검증 결과:
남은 위험:
```

## Worker 중단 조건

Worker는 다음 상황에서 임의로 진행하지 않는다.

- 실시간 오디오 경로 변경
- signaling protocol 변경
- 인증/세션 구조 변경
- P2P/Relay 구조 변경
- VST 역할 변경
- CI/build 설정 변경
- 테스트 실패 원인 불명확
- 성능 수치 근거 없음

## 판단 우선순위

1. 실시간 오디오 안정성
2. 아키텍처 경계 유지
3. 작은 변경 단위
4. 검증 가능성
5. 사용자 흐름 단순성
