# docs/ai/work-log.md

## 목적

이 문서는 TempoLink 개발 중 발생한 작업 흐름을 매일 기록하기 위한 기준이다.

목적은 포장된 결과물이 아니라 실제 개발 과정을 남기는 것이다.

기록 대상은 다음이다.

- 오늘 작업한 내용
- 발생한 이슈
- 막힌 지점
- 확인한 원인
- 시도한 해결 방법
- 실패한 접근
- 임시 처리
- 다음에 이어서 해야 할 일
- 나중에 다시 봐야 할 의사결정

## 기록 위치

작업 로그는 날짜별로 남긴다.

```txt
docs/work-log/YYYY-MM-DD.md
```

예시:

```txt
docs/work-log/2026-05-29.md
```

하루에 여러 작업을 했다면 같은 파일에 이어서 기록한다.

## 기록 원칙

- 사소한 이슈도 남긴다.
- 실패한 접근도 남긴다.
- 추측과 확인된 사실을 구분한다.
- 임시 해결은 임시라고 표시한다.
- 나중에 이어서 작업할 수 있도록 현재 상태를 남긴다.
- 수치는 측정한 경우에만 적는다.
- 작업 결과보다 흐름을 우선한다.

## 작성 타이밍

Agent는 다음 시점에 작업 로그를 갱신한다.

- 작업을 시작했을 때
- 에러나 막힘이 발생했을 때
- 원인을 확인했을 때
- 해결 방법을 선택했을 때
- 임시 우회를 추가했을 때
- 작업을 마무리했을 때

```md

-

  -

-

```

## 간단 기록 형식

작업이 작으면 아래 형식만 사용한다.

```md
## <시간 또는 작업 제목>

- 작업:
- 이슈:
- 원인:
- 처리:
- 남은 것:
```

## Agent 기록 규칙

Agent는 작업 중 의미 있는 변화가 생기면 `docs/work-log/YYYY-MM-DD.md`에 기록한다.

작업 로그에는 다음을 숨기지 않는다.

- 실패한 명령
- 빌드 오류
- 테스트 실패
- 원인을 모르는 상태
- 임시 처리
- 나중에 제거해야 하는 Mock
- 아직 검증하지 못한 부분

## 금지

- 해결되지 않은 문제를 해결된 것처럼 기록하지 않는다.
- 추측을 사실처럼 기록하지 않는다.
- 실패한 검증을 생략하지 않는다.
- 임시 구현을 최종 구현처럼 기록하지 않는다.
- 작업 로그를 포트폴리오 문장처럼 꾸미지 않는다.
